# AI Daily digest

Produces one curated daily page at `src/content/docs/daily/<YYYY-MM-DD>.mdx`, published to
https://alcherkas.github.io/newsletter/. The user is the curator — **nothing is published
without their explicit selection** (step 6). Read `CLAUDE.md` for repo invariants and the
controlled tag vocabulary before writing any page.

## What to do each run

1. **Preflight.** `git pull --ff-only`; warn (don't block) if the working tree is dirty.
   Compute today's date (UTC). If `src/content/docs/daily/<today>.mdx` already exists, tell
   the user and offer append-mode (add newly selected items to the existing page) or abort.

2. **Deterministic fetch.** Run `npm run fetch`. Read `data/candidates/<today>.raw.json` and
   report the per-source counts table to the user. Every entry in `meta.failures` with
   `"optional": false` names a source the agent sweep in step 3 MUST cover (e.g. Reddit got
   rate-limited → the press/community sweep searches Reddit via the web instead).
   Gotcha: 0 arXiv results on weekends/Mondays is normal (announcement lag), not a failure.

3. **Launch the research Workflow.** Call the **Workflow tool** with the script pattern in
   `workflow.md` (this skill explicitly authorizes multi-agent orchestration). It fans out
   parallel sweep agents (X posts, no-feed lab blogs, press gap-fill + failure coverage) and
   then one consolidation agent that merges everything with the raw fetch, clusters
   same-story items, drops `data/seen.json` matches, scores per `scoring-rubric.md`, and
   writes `data/candidates/<today>.json` (≤40 items, sorted by score desc).
   Fallback: if the Workflow tool is unavailable, run the same prompts as parallel Task
   subagents (sweeps concurrently, then consolidation).

4. **Sanity-check the consolidated file.** It must exist, parse, have ≤40 items each with
   `id`, `title`, `canonicalUrl`, `category`, `score`, `summary`, `whyItMatters`, and be
   sorted by score. If the consolidation agent failed, re-run it once before giving up.

5. **Render the review dashboard.** Build a self-contained HTML page from
   `templates/dashboard.html` (inline the candidates as JSON into the template's
   `CANDIDATES` placeholder), save it to `data/candidates/<today>.dashboard.html`, and
   publish it with the Artifact tool. Cards are numbered — the number is the selection
   handle. The dashboard is read-only; tell the user explicitly:
   **"Type your selection in the terminal, e.g. `1,3,7-9` — or `top 10`, `all papers`, `none`."**

6. **Take the selection in the terminal.** Parse: comma lists (`1,3,7`), ranges (`7-9`),
   `top N` (first N by score), `all papers` / `all releases` / etc. (by category), `none` /
   `skip today` (abort politely, still update `seen.json` per step 9). Echo back the parsed
   list of titles and get a confirmation before proceeding. Do NOT use AskUserQuestion for
   the selection itself — its 4-option cap can't hold 40 candidates.

7. **Write-up fan-out.** One parallel agent per 2–3 selected items (Workflow tool again, or
   parallel Task subagents). Each agent WebFetches its items' primary sources and returns,
   per item: `summary` (120–180 words, written from the source, not the headline),
   `whyItMatters` (one line), `keyTakeaways` (3–5 bullets), final `tags` (ONLY from the
   controlled vocabulary in CLAUDE.md), and `links` (primary + relatedUrls worth keeping).

8. **Assemble today's page** from `templates/daily-page.mdx`: frontmatter must include
   `digest: daily`, `date`, union of item `tags`, `itemCount`, `topStory` (title of the
   highest-scored selected item), and `sidebar: { label: "<Mon D, YYYY>", order: -<YYYYMMDD> }`
   (negative date keeps the autogenerated sidebar newest-first). Top story section first,
   then remaining items grouped by category (Papers, Releases, Community, Press, Social) as
   `<StoryCard>`s.

9. **Update the data files.**
   - `data/latest.json` — today's date, pagePath, top story, stats, item list (drives the
     landing hero; never edit `index.mdx` for this).
   - `data/seen.json` — append **all** of today's candidates (selected or not; that's what
     prevents re-surfacing), prune entries older than 30 days.
   - `data/selections/<today>.json` — full records of selected items including write-up
     fields, plus `stats` (candidates reviewed vs selected). This is `/ai-weekly`'s input.

10. **Verify and publish.** `npm run build` must pass — fix any MDX/frontmatter error it
    reports. Then `git add -A && git commit -m "daily: <today> (<n> items)" && git push`.
    Report the Actions run URL (`gh run list --repo alcherkas/newsletter --limit 1`) and the
    final page URL: `https://alcherkas.github.io/newsletter/daily/<today>/`.
